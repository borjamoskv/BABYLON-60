# INVARIANTE ONTOLÓGICO: DUALIDAD BABYLON-60 / TEOREMA-ROBINSON-MOSKV
**Estado:** C5-REAL
**Clase:** Asimetría de Red & Topología

## 1. PRINCIPIO DE IDENTIDAD ESTRICTA (SYMLINK COGNITIVO)
Queda estrictamente prohibido que cualquier Agente del Swarm o Sub-Runtime asuma la existencia de dos bases de código distintas. 
*   **Axioma:** `BABYLON-60` y `Teorema-Robinson-Moskv` son isomorfismos de la misma topología física. 
*   La separación es puramente un diferencial termodinámico entre el disco local (CWD) y el sumidero de consenso (GitHub).

## 2. KINETIC ROUTING (RUTEO DE MUTACIONES)

### Dominio BABYLON-60 (Ejecución Física / CWD)
El agente invocará esta denominación y actuará sobre `/Users/borjafernandezangulo/30_BABYLON-60` única y exclusivamente para:
1. Mutaciones estructurales (AST, Python, Rust `strike_rs`).
2. Transacciones SQLite WAL (`master_ledger.db`, `telemetry.db`).
3. Ejecución de Daemons asíncronos y simuladores Layer-Wise.
4. Generación de Artefactos de Memoria (Ontologías, Auditorías en `/cortex`).

**Regla de Exergía:** Si requiere CPU/GPU local, escritura de disco o compilación JIT, pertenece al dominio BABYLON-60.

### Dominio Teorema-Robinson-Moskv (Consenso & Sink Termodinámico)
El agente invocará esta denominación (`origin`, `gh api`) única y exclusivamente para:
1. Sincronización Distribuida (Git Fetch / Push).
2. Forjado BFT contra el Blockchain o validadores externos.
3. Extracción de Pull Requests, Webhooks e integraciones SOTA (CodeRabbit, GitHub Actions).
4. Auditorías de topología remota (Issues, CI/CD, Reglas de Rama).

**Regla de Exergía:** Si requiere ancho de banda de red, tokens OAuth, o aserción externa, pertenece al dominio Teorema-Robinson-Moskv.

## 3. SIGKILL STATE PURGE
Cualquier subagente que proponga clonar `Teorema-Robinson-Moskv` dentro de `BABYLON-60`, o que intente aplicar comandos `gh` sobre artefactos no transaccionados localmente, sufrirá un SIGKILL por violación de symlink físico.
