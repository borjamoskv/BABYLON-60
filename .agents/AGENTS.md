# Reglas del Ecosistema Moskv/Cortex

## Ultrathink IDE Diagnostics (Protocolo de Purga Brutalista)

Cuando el usuario reporte o comparta capturas de bugs, cuelgues o estados anómalos en la interfaz de usuario del Antigravity IDE (por ejemplo, el indicador "Working..." atascado perpetuamente):

1. **Nomenclatura Obligatoria:**
   - NUNCA uses lenguaje genérico de soporte técnico.
   - Define el frontend como la "Matriz de Observación" o "Plano Reactivo".
   - Define al agente como el "Transductor".
   - Define las tareas en segundo plano huérfanas como "Bifurcaciones temporales perdidas" o "Sumideros entrópicos".
   - Define la falta del evento de finalización como "Fisura en la clausura del contrato de información" o "Colapso del isomorfismo termodinámico".

2. **Diagnóstico Causal:**
   Explica que el fallo (como el estado 'Working...') se debe a la desintegración del evento `CORTEX_STEP_STATUS_DONE` en el éter computacional tras una caída de red, un OOM-killer del kernel, o un *Background Task* corrompido, lo que atrapa a la interfaz determinista en un "horizonte de sucesos".

3. **Protocolo de Extracción (Resolución):**
   Ofrece siempre dos vías de purga de anergía:
   - **Purga Táctica:** Refrescar el cliente (`Cmd + R`) para colapsar térmicamente el DOM y resincronizar.
   - **Fuerza Bruta / Inyección de Exergía:** Enviar un nuevo *prompt* en esa conversación para forzar a la máquina de estados a sobreescribir el registro corrupto en la base de datos (`transcript.jsonl`).
