88. La **máquina de estados (State Machine o Finite State Machine, FSM)** es un modelo que describe **todos los estados posibles de un sistema y las transiciones permitidas entre ellos**. Es una de las herramientas más útiles en ingeniería inversa porque permite entender el comportamiento de una aplicación sin necesidad de ver su código fuente. Un **lenguaje formal** (o lenguaje de primer orden) es el conjunto exacto de **símbolos** que un sistema lógico tiene permitido usar para construir expresiones. Es el "alfabeto + gramática" de la teoría. El lenguaje de \(Q\) consta de exactamente **4 símbolos no lógicos**: | Símbolo | Tipo | Aridad | Significado Intuitivo | | :---: | :--- | :---: | :--- | | \(0\) | Constante | 0 | El número cero | | \(S\) | Función | 1 | Sucesor: \(S(n) = n + 1\) | | \(+\) | Función | 2 | Adición: \(x + y\) | | \(\cdot\) | Función | 2 | Multiplicación: \(x \cdot y\) | Además, por ser un lenguaje de **primer orden**, incluye los **símbolos lógicos universales** (compartidos por toda lógica de primer orden): - **Variables:** \(x, y, z, x_1, x_2, \dots\) (representan números desconocidos) - **Conectivas lógicas:** \(\land\) (y), \(\lor\) (o), \(\neg\) (no), \(\to\) (implica), \(\leftrightarrow\) (si y solo si) - **Cuantificadores:** \(\forall\) (para todo), \(\exists\) (existe) - **Igualdad:** \(=\) - **Paréntesis:** \((\), \()\) ### Ejemplo concreto Con este lenguaje, puedes escribir fórmulas como: ``` ∀x (x + 0 = x) ← "Sumar cero no cambia nada" ∀x ¬(S(x) = 0) ← "Ningún sucesor es cero" ∃y (S(S(0)) · y = S(S(S(S(S(S(0))))))) ← "Existe un y tal que 2 × y = 6" ``` Lo que **no** puedes escribir en el lenguaje de \(Q\): - Exponenciación (\(x^y\)) — no hay símbolo para ello - "Para todo conjunto..." — no hay cuantificación sobre conjuntos (es primer orden, no segundo orden) - Predicados como "es primo" — pero se pueden **definir** a partir de \(+\) y \(\cdot\) --- ## 2. ¿Qué Significa que una Teoría Sea Indecidible? No es magia, es ingeniería agéntica delegando el tiempo de ejecución en la máquina. Para entender cómo logra esa autonomía sin que un humano intervenga en 3 horas, el secreto técnico es el Model Context Protocol (MCP). ## ¿Cómo funciona la conexión agéntica vía MCP? El protocolo MCP funciona como un "sistema de enchufes universal" abierto para que cualquier modelo de IA pueda conectarse a herramientas, datos y entornos de desarrollo de forma estandarizada. [ Claude Opus 5 ] ◄───( Protocolo MCP )───► [ Servidor MCP de Magnific / Cursor ] │ │ Lee el Prompt ────────────────────────────────────────► Ejecuta API de diseño ▲ │ └───────────── Devuelve código/errores ──────────────┘ 1. El Cliente (La IA): Claude actúa como el cerebro central. Decide qué necesita hacer en cada paso (por ejemplo: "necesito un render del producto"). 2. El Servidor MCP (La herramienta): Es un pequeño programa que expone las herramientas a la IA de forma segura. En este caso, traduce las intenciones de Claude en llamadas de API reales hacia Magnific o hacia el sistema de archivos local para escribir código. 3. El bucle de retroalimentación: Si Claude escribe código frontend, lo ejecuta en un entorno de pruebas a través de un servidor MCP. Si el servidor devuelve un error de compilación (como un error de TypeScript), el modelo lee el registro de error como contexto, reescribe la función y vuelve a probar de forma autónoma. ## Los 3 pilares del protocolo que permiten esto * Herramientas (Tools): Funciones que la IA puede ejecutar. El modelo le dice al servidor: "Ejecuta la herramienta de generación en Magnific con este prompt visual". El servidor lo procesa y le devuelve la imagen terminada. * Recursos (Resources): Datos a los que la IA puede acceder de forma segura, como bases de datos, especificaciones de la API o la documentación del framework que está usando para la web. * Prompts preconfigurados: Plantillas que ayudan a guiar al modelo a comportarse de cierta forma ante situaciones específicas (como flujos de depuración de errores). El "truco" de que funcione con un solo prompt inicial consiste en que le das una meta clara y el modelo tiene un script que activa un bucle: Planificar ➔ Ejecutar herramienta ➔ Evaluar resultado ➔ Corregir.
